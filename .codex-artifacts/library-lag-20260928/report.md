# 社区版卡顿排查与验证（2026-09-28）

已修复另一处主线程长阻塞：主页完整播放统计在真实曲库备份上耗时 16,619ms，其中专辑聚合占 16,576ms。将逐记录关联的最新记录查询改为分组窗口排序后，总耗时降至 80ms；除 generatedAt 外返回对象完全一致。完整/筛选统计同时覆盖，并将统计查询接入只读工作线程。

退出流程现在等待查询线程关闭；正常关闭先让 SQLite 当前查询完成，随后关闭工作线程，5 秒超时后才强制终止。最终 UI 测试正常退出（exit code 0）。

## 环境与范围

Electron 42.3.3，Windows x64。使用一致性备份曲库（可见歌曲 18,709 首、专辑 2,939 张、艺术家 4,692 位）和固定的 renderer 构建，避免并行任务 HMR 干扰。测试副本关闭安全模式控制台及最小化超低功耗切换，播放验证使用共享输出；原始曲库未被清空或重建。

UI 输入通过实际点击、键入、滚轮和双击完成。主进程与界面分别每 50ms 记录心跳间隔。PlaybackGetStatus 校验真实 currentTrackId、playing 状态及 positionMs 推进；没有把 Promise 或 loading 状态当作播放成功。
